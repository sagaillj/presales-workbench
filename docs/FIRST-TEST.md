# Verify the first real orientation

This validates the approved bounded orientation from ONBOARDING.md. All onboarding stays in Codex; no browser setup screen is part of this flow. It does not
require a minimum number of tasks, CRM writes or a sample-first ritual.

1. **Runtime and location:** confirm the standalone folder, working Python 3.10+
   and `workbench.py doctor`. Verify the actual server and local URL. Preserve an
   existing workspace and do not stop an unrelated process to claim the port.
2. **Consent and identity:** retain the explicit chat authorization for the
   selected work sources and whether recurring upkeep was included. Verify the
   current user's account, work profile, IANA time zone and CRM portal/ownership
   mapping where accessible. Missing facts remain unknown.
3. **Full bounded audit:** review the approved own Slack profile/DMs/group
   DMs/current deal channels/tags, incoming and sent email, Calendar, own CRM
   deals/CALLs and available linked Zoom/Gong transcripts, and own Hex month/quarter.
   Use the windows in ONBOARDING.md. Read latest replies and source evidence;
   source failure is a gap, not an empty successful search.
4. **Useful output:** save and import only actual outstanding user/SE duties with
   author, time, quote/excerpt, source link, stable ID and useful prepared work.
   Preserve resolved asks, user edits and completed decisions. A complete quiet
   pass may yield zero tasks; partial coverage cannot prove nothing needs doing.
5. **Visible verification:** after the first full review/import, open the normal app at `/?mode=personal` on the actual port and
   check the resulting task/draft/source details and metrics coverage. Exactly one markable
   Customer/Internal orientation task per lane stays outside real-work counts and savings;
   test Done, Undo and persisted completion without recreating cards on a rerun.
   No fictional sample data may appear as actual personal work.
6. **Receipt:** run `python3 workbench.py record-orientation <actual-receipt.json>`
   only after the real source pass and import. Use actual coverage, source URLs,
   import fingerprints and matching saved task quotes; explain a quiet result.
   The receipt records evidence and is not a new permission grant.
7. **Agreed upkeep:** if the earlier chat consent included it, create/reuse the
   native weekday main review at 17:30 in the verified time zone. Optional daytime
   checks remain OFF unless the user explicitly opts in and light.enabled is true;
   only then create their native job at the saved times. Read back actual enabled
   job IDs/rules/status and record the schedule receipt. Preserve existing user
   choices. See SCHEDULING.md. Without recurring consent, schedules stay off.
8. **Local checks:** run `python3 scripts/test_starter.py` and
   `python3 workbench.py doctor`. They validate local behavior, not remote source
   access, a CRM write or a successful scheduled execution.

A ready result has verified local access, honest bounded-source coverage, correct
personal output or a genuinely quiet result, and native readback for any agreed
upkeep. Otherwise report partial with the working URL and only the necessary
remaining gaps. Writes, sends, recording changes and purchases need their own
specific approval; this first test authorizes none of them.

Optional sample exploration can test Done → Undo → saved Completed → Reopen in
`/?mode=demo`. That touches only sample progress, is not onboarding evidence, and
never substitutes for the real read-only orientation.

For failures, report the exact failing command/response and appropriate next
step. A missing runtime requires the official installation flow and specific
approval described in ONBOARDING.md. An auth blocker needs the supported native
handoff. Do not request credentials, bypass organization policy or manufacture a
successful result to fill the page.
