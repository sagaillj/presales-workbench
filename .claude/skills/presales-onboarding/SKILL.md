# Presales Onboarding

Follow ../../../docs/ONBOARDING.md. Keep onboarding in the assistant chat with no browser setup form. After prerequisites, run the first full review now, import genuine results, then open normal Workbench. Include the two automatically provisioned markable orientation tasks, preserve their completions and exclude them from real-task evidence and savings. Start with the short get-acquainted and bounded read-only orientation/routine-upkeep choice. Use two or three concise checkpoints, not an identity form, time questions or a forced sample/empty-preview gate. Reuse explicit current-chat authorization. Check local Python proactively and use a specifically approved official installation route only when needed. Orient from the user's own approved sources, preserve unknowns, reconcile latest answers and import real source-backed work without a task quota. Follow ../../../docs/FIRST-TEST.md and ../../../docs/SCHEDULING.md for actual receipts, native job creation/readback after recurring consent, and a ready/partial closeout with the verified local URL. Preserve existing workspaces and progress. No inherited identity, personal permissions, automatic external writes or global settings changes.

Default recurring setup creates only the agreed daily main review. Daytime communication checks start OFF; saved suggested times do not enable them. Create their native job only after explicit user opt-in and schedules.light.enabled is true. Preserve existing user choices and verified active legacy light jobs on upgrade; never stop them because the new-user default changed.
